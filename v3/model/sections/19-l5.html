L5 Help subflow — the agent-initiated ask

An ACTIVE agent can ask its human for help mid-step — a question, not a decision — and continue exactly where it was with the answer folded into its context. The v1 grounding is WAITING_HUMAN (an active agent asks, round ≥ 1, same-context resume, no routing). This is the first level built ON the five kernel primitives: per the kernel-primitives memo's paper test (§8), L5-core is six declarations over the existing contracts — one new operator intent (HELP_REPLY) and zero new machinery.

The boundary. A help ask is not a decision: no declared keys, no decisions map, no routing — the reply enriches, it never selects. Kernel-level "same-context resume" means the same position plus an enriched handoff; keeping the agent's session alive across the wait is adapter territory (L0c / the executor), not kernel state. And the ask is emit-opened: the errand contract reserved this opener at LC2, and the help ask is its first live instance — the kernel does not open this errand on arrival; the actor opens it mid-step.

Runtime A concrete trace (mid-step question, same-round resume)

1
the implementer agent, ACTIVE on implement (round 2), hits an ambiguity: "OAuth or API-key auth for the webhook?"
it emits HELP_REQUEST { op_id, expected_version, expected_role, payload: { question, refs: [diff] } } — the ordinary actor envelope, through HANDLE's ordinary Admission ladder
2
the kernel parks: WAITING(help_pending) + a durable HELP_REQUEST fact (fresh request_ref) — one atomic commit
implement declares help: ✓, HELP_REQUEST ∈ capability ✓, question present ✓ ⇒ park; current_step and round do NOT move. Post-commit: a HelpRequest leaves for binding[operator] with the question + context
3
a second HELP_REQUEST arrives (the agent's client retried)
same op_id ⇒ Duplicate (the fact entry carries it); a different emit would hit Rejected(not_active) — the instance is WAITING now, and the blocking home holds ≤ 1 open ask
4
the operator answers: HELP_REPLY { op_id, expected_version, request_ref, reply: "API-key; OAuth is phase 2 — see ADR-14", by }
admitted via admit_input (op_id · help_pending · request_ref correlation · CAS · operator authority) ⇒ HELP_REPLIED fact + back to ACTIVE — stay: same implement, still round 2, no arrival effects
5
the next dispatch goes out — same step, handoff = original ⊕ the answered ask
help_exchange_for derives the question→answer pair from the transcript (by request_ref); the agent continues the SAME work item with the answer in its packet — no round burned, no position moved

Pseudocode The help handlers (diff vs L4)

Six declarations over the primitives: a HANDLE branch (the emit-opened errand's opening), a park+fact helper, a Directive member, one operator-intent completion on the hardened ingress, a transcript-derived handoff enrichment, and a load-time validator. Every guard is an existing contract with new parameters:

The HELP_REQUEST emit is a separate HANDLE branch, deliberately not a transitions key: it has no target, calls no apply_target_entry_effects, and its commit parks. One emit produces one transcript entry — the HELP_REQUEST fact IS the op_id-carrying record (no generic envelope append beside it). The reply path is the SUBMIT_DECISION contract family with different parameters, and its commit is the stay route's first live instance: same position without re-arrival — unlike a self-target, which genuinely re-arrives through the shared arrival. The reply's one required field is validated with the generic missing_required_field guard (one vocabulary — contract-fixed rather than template-declared, deliberately not a new reject name). Help emits are deliberately not gated at L5: the L2 pipeline filters state-moving transitions, and an ask moves no workflow state beyond parking — policy filters on asks are an open deferral (Absent).

Domain What L5 adds

Help — an ask, a wait, and a transcript pair
help_pending (wait kind)
one more value on the L0d WAITING axis — the precedented extension point. Blocking variant: the marker homes in the single wait slot (≤ 1 open ask is this home's property); the record-collection-homed non-blocking variant is declared but deferred
HELP_REQUEST / HELP_REPLIED (transcript)
the ask fact (op_id, request_ref, step_id, round, question, refs) and the completion fact (op_id, request_ref, reply, by) — the pair is auditable and step/round-filterable from the record alone, matched by request_ref
HelpRequest (value)
the agent-initiated ask — a Directive member (addressee: operator), derived post-commit from wait.kind = help_pending; free-form reply, deliberately NOT a decisions map. The P5 maturation path the memo names: HumanDecisionRequest (L3) → HelpRequest (L5) → external-token asks (L8)
step.help (template)
opt-in per agent step, with a declared payload schema (question required); puts HELP_REQUEST into the role's capability at that step; validate_help_config fails a bad shape at create
stay (route)
the ChoicePoint contract's reserved route value, now live: same current_step, advances_round = false, no arrival effects; the enriched handoff (original ⊕ reply) belongs to the next dispatch, derived by help_exchange_for

Evidence Why we accept L5 for now

  • Scenario coverage: a mid-step ambiguity parks the run and asks the bound operator; the answer resumes the SAME step and round with the exchange in the handoff; a retried emit is Duplicate; an ask at a step with no help: is rejected before any state change; an unanswered ask blocks (the human_gate's accepted tradeoff, timeout → L9).
  • Invariant coverage: one-visible-transition park ✓; one emit, one entry ✓; stay is not an arrival ✓; the reply rides the record ✓; undeclared/unauthorized asks start nothing ✓; the blocking home's ≤ 1 open ask ✓ — and all L0a–L4 + LC1–LC4 invariants still hold.
  • Paper-test reconciliation (memo §8): six declarations promised, six landed — the op + schema, the wait kind + durable fact, the Directive member, the completion on the hardened ingress, the stay route (its reserved slot resolved), and the blocking/non-blocking variant (blocking shipped, non-blocking declared + Absent). One scope choice the paper test left open is recorded in the memo §9: help emits are not gated at L5.
  • Known gaps (intended): timeout/escalation (L9), non-blocking form (later), durable channels (L8), routing beyond the binding (L8/L10), help-emit gating (later), deferred-rework stash (L6/L9). Each is in Absent.
  • Decision: accepted as the L5 baseline (light evidence per playbook §2.1). Block A ≈ the full local pairflow-v1 feature set with this level landed.
