## Context (non-normative by declaration)

Successor of `ch13-context-block`, superseded 2026-08-05; inheritance
verified by the P4 completeness pass (review record:
`v3/implementation/ch13-rederivation-arm/p4/`).

**The declaration authority.** This is the first contract authored ON
the ADR-019 schema substrate: every structural rule of this surface
lives as DATA in `v3/src/definition/schema/templateFormat.ts`, and this
contract states DECISIONS and cites those declarations by TAG (ADR-019
D4 — one authority, pointers everywhere else); where a row glosses an
attribute in passing, the gloss is non-binding paraphrase and the
declaration's bytes govern. The ratifying act binds that file's bytes
beside this file's C-rows (the contract-draft template's schema lock)
— and a LATER edit of the declaration (P5's own duties included) turns
the lock red until a re-ratifying act records the new bytes: designed,
not an accident. Citation closure (every tag cited exists; every
ch13v2-rowed node is cited) is checked mechanically at review — no
standing code check exists for it yet; prose restatement is the review
panel's to catch.

**Business invariant.** Context blocks are actor-facing communication:
deterministic prose delivered with the dispatched packet so an actor
hears an operating rule before acting. They influence no verdict and no
kernel decision — enforcement lives elsewhere; this surface only speaks.

**Control model.** A single catalog at template level owns all body text. Three
ref positions point into it by id: role-level and step-level
`promptConcernRefs` inside the agent-config maps, and `contextBlockRefs`
on a gate binding. Authored KEY spellings follow the standing camelCase
rename culture over the model's snake_case names, while model-defined
TOKEN VALUES keep the model's exact spelling — pinned here because the
plan requires this surface to fix the relation explicitly. The declared
schema validates catalog and refs at admission on both channels;
rendering happens at dispatch as a deterministic computation over
admitted inputs.

**Read-path.** Admission reads the authored value — one declaration,
both channels; rendering reads only the admission-produced surfaces
(C13); the run-scope channel is never read (C5).

**Forbidden fallback.** Rendering never drops a ref and never tolerates
a malformed catalog — admission lets neither situation through. No new rejection or issue name: the one issue code is the
ratified `unresolved_context_block_ref`.

**Allowed resolution / missing data.** A template that issues no refs
and declares no catalog is fully legal (every pre-ch13 file). A
template whose refs find no valid entry fails admission with per-site
findings.
