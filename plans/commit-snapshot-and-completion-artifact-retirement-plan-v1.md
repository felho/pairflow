# Plan: Done Package Hard Removal And Commit Result Cutover

## Objective

Remove the `done-package` / `DONE_PACKAGE` approval-package model from Pairflow commit finalization as if it had never been a supported commit boundary.

The replacement is not another approval package and not another prose artifact. The target commit model is a minimal technical commit result:

1. Git creates the bubble-branch commit.
2. Pairflow records a `COMMIT_RESULT` transcript event with only technical commit facts.
3. Pairflow transitions the bubble state from `APPROVED_FOR_COMMIT` through `COMMITTED` to `DONE`.
4. CLI/API result surfaces report the same technical commit facts.

No compatibility rollout is intended. The final merged state must not require, generate, sync, read, or document `artifacts/done-package.md` as part of first-party runtime behavior.

## Target Architecture

1. `done-package.md` does not exist as a commit input.
2. `done-package.md` is not auto-generated by `bubble commit`.
3. `DONE_PACKAGE` is removed from the active protocol message type family.
4. Commit finalization emits `COMMIT_RESULT`, not `DONE_PACKAGE`.
5. `COMMIT_RESULT` has no prose summary and no approval-package fields.
6. `COMMIT_RESULT` payload metadata contains:
   - `commit_sha`
   - `commit_message`
   - `staged_files`
7. `commit_message` comes from `--message` when provided; otherwise it remains the current default:
   - `bubble(<bubbleId>): finalize`
8. The current `--auto` option is replaced by `--stage-all`.
9. `--stage-all` means only:
   - stage all current worktree changes before commit
   - equivalent intent: `git add -A`, then commit
10. The old `--auto` meaning is removed from the target model because it included done-package generation.
11. Local worktree crash recovery after a successful git commit is not expanded by this plan.
12. If `git commit` succeeds and Pairflow crashes before final state completion, the existing class of problem remains operator/manual recovery; this removal plan must not introduce a new automatic recovery mechanism.

## Current Codebase Check

The current codebase binds `done-package` into several runtime surfaces:

1. Local commit preparation:
   - `src/v11/application/commit/commitCommandApi.ts`
   - reads or creates `artifacts/done-package.md` before the git commit.
2. Done-package artifact handling:
   - `src/v11/application/commit/commitDonePackage.ts`
   - requires a non-empty artifact unless `--auto` is used.
   - auto-generates prose from transcript summaries when `--auto` is used.
3. Commit finalization transcript:
   - `src/v11/shared/commit/commitCommandFinalizationMutation.ts`
   - appends `DONE_PACKAGE` with summary, done-package path, staged files, commit message, and commit SHA.
4. Commit CLI:
   - `src/v11/application/commit/commitCliCommand.ts`
   - documents `--auto` as auto-stage plus auto-generate done-package.
5. Remote commit continuity:
   - `src/v11/infrastructure/executor/ssh/sshBubbleCommitCommand.ts`
   - expects remote commit output and local sync-back to include done-package content.
6. Start/resume and docs surfaces:
   - some first-party docs and command context still describe done-package as a completion or closure artifact.

These bindings are implementation debt from a wrong product idea. The plan removes the model rather than preserving a compatibility surface.

## Guiding Principles

1. `business_invariant`
   - A bubble commit is complete because Pairflow created a git commit and completed its state transition, not because a prose approval package exists.
2. `control_model`
   - Commit finalization is controlled by the commit runtime.
   - Human-readable summaries are not commit authority.
3. `read_path_rule`
   - First-party runtime consumers read commit completion from state, transcript `COMMIT_RESULT`, command result, and git.
   - No first-party runtime consumer may require `done-package.md`.
4. `forbidden_fallback`
   - Do not preserve `DONE_PACKAGE` as a fallback event.
   - Do not preserve `done-package.md` as a fallback artifact.
   - Do not introduce a new prose completion artifact under another name.
5. `allowed_resolution_path`
   - Replace the commit finalization event with `COMMIT_RESULT`.
   - Replace CLI `--auto` with `--stage-all`.
   - Align local, remote, CLI/API, tests, and docs in the same hard-removal sequence.
6. `missing_data_rule`
   - Missing `done-package.md` is not an error.
   - Missing `COMMIT_RESULT` after a crash is not auto-recovered by this plan; it remains operator/manual diagnosis.
7. `baseline_preservation`
   - Existing deterministic git commit reuse, clone retry, and source-branch sync behavior is preserved baseline behavior.
   - This plan does not expand that behavior into new automatic crash recovery.
   - When the preserved baseline finalizes a valid commit SHA, finalization writes `COMMIT_RESULT` instead of `DONE_PACKAGE`.

## Implementation Window Assumption

1. No active remote bubbles need to be supported while this plan is being implemented.
2. This assumption allows local-first implementation work without designing temporary remote compatibility for in-flight remote bubbles.
3. This assumption does not reduce the target-state requirement: remote commit must support the same hard-removal model before the plan is accepted as complete.
4. A partial implementation may exist on a development branch or bubble branch, but it must not be treated as a mergeable target state while local, remote, CLI/API, tests, and live docs still disagree.
5. If active remote bubbles must be supported during implementation after all, this plan must be re-reviewed before implementation continues.

## Mergeability Model

This plan separates implementation slicing from mergeability.

1. `integration_slice`
   - A task may be implemented as an intermediate slice on a development branch or bubble branch.
   - An integration slice may temporarily add `COMMIT_RESULT` while old producers still exist, or cut over local behavior before remote behavior.
   - An integration slice is not automatically a mergeable product state.
2. `mergeable_target_state`
   - Main may only be considered complete when protocol, local commit, remote commit, shared command/API result surfaces, CLI/API inputs, tests, and live docs all converge on the no-done-package model.
   - No phase may be described as independently mergeable if it leaves a first-party runtime path depending on `DONE_PACKAGE`, `done-package.md`, `donePackagePath`, or `--auto`.
3. `contract_cutover_dependency`
   - The shared command input contract and shared command result contract are separate cutover axes.
   - The `donePackagePath` result-field removal is owned by the local producer cutover because keeping that result authority alive preserves the removed done-package model; Phase 2 must update direct compile consumers and projections that depend on `CommitBubbleResult`.
   - The `auto` to `stageAll` request/input rename is split across Phase 3A CLI/application foundation and Phase 3B UI-router/frontend consumer alignment.
   - Both axes must be closed across CLI, application API, and UI/router API before the target state is accepted.
   - Remote execution transport, SSH output parsing, remote marker handling, and sync-back are owned by remote alignment.

## Scope

### In Scope

1. Remove local commit dependency on `artifacts/done-package.md`.
2. Remove done-package auto-generation.
3. Remove `DONE_PACKAGE` from active protocol validation and transcript emission.
4. Add `COMMIT_RESULT` protocol support with a closed technical fieldset.
5. Emit `COMMIT_RESULT` after successful git commit and before final state transition.
6. Update commit result contracts so first-party callers receive technical commit facts without `donePackagePath`.
7. Rename commit CLI `--auto` behavior to `--stage-all`.
8. Align remote commit execution and sync-back with `COMMIT_RESULT`.
9. Update first-party tests and docs that describe current commit behavior.

### Out Of Scope

1. Building automatic local worktree recovery for crash-after-git-commit scenarios.
2. Preserving `done-package` compatibility for downstream or archived workflows.
3. Creating a replacement approval package or completion prose artifact.
4. Rewriting archived historical task files unless a live runtime/documentation link depends on them.
5. Changing approval semantics before commit; this plan starts after approval has already produced `APPROVED_FOR_COMMIT`.

### Phase 1: Commit Result Contract

Goal: define and validate the new technical event without activating a mixed finalization model.

Required changes:

1. Add `COMMIT_RESULT` to the active protocol message type family.
2. Define the target `DONE_PACKAGE` removal contract:
   - `DONE_PACKAGE` is not a target-state first-party commit finalization event.
   - `DONE_PACKAGE` hard removal from active validation/emission happens only when the local and remote commit producers have been cut over.
   - Any temporary dual-validation state is an integration slice only, not a mergeable target state.
3. Validate `COMMIT_RESULT` payload as a closed technical fieldset:
   - require non-empty `metadata.commit_sha`
   - require non-empty `metadata.commit_message`
   - require `metadata.staged_files` as a non-empty string array
   - reject `payload.summary`
   - reject done-package fields
   - reject unknown metadata keys
4. Add protocol tests for accepted and rejected `COMMIT_RESULT` envelopes.

Exit criteria:

1. `COMMIT_RESULT` can be validated.
2. `DONE_PACKAGE` is documented as removed from the target finalization contract.
3. No prose summary is part of the new commit result contract.
4. The phase does not require remote commit to remain operational in a mixed local/remote transition state.
5. If this phase lands separately as an integration slice, downstream producer and consumer cutover must remain in the same integration closure before main is considered complete.

### Phase 2: Local Commit Producer Cutover

Goal: make local `bubble commit` produce the new model and stop touching done-package, while keeping final merge gated on remote alignment.

Required changes:

1. Remove `readOrCreateDonePackage` from local commit preparation.
2. Delete or retire `commitDonePackage.ts` from the active local commit path.
3. Replace `appendDonePackageEnvelope` with `appendCommitResultEnvelope`.
4. Keep current side-effect ordering:
   - validate state is `APPROVED_FOR_COMMIT`
   - validate staged files or stage all when requested
   - run git commit
   - append `COMMIT_RESULT`
   - transition state to `COMMITTED`
   - transition state to `DONE`
5. Do not add new automatic recovery after the git commit point.
6. Remove `donePackagePath` from the shared application commit result contract and update direct compile consumers/projections that read that type, including root CLI output and UI-router result typing as needed. This is result-surface contraction, not Phase 3 request/input activation.
7. Remove local `done_package_path` lifecycle metadata from local `bubble_committed` events.
8. Keep `auto` only as temporary local stage-all input spelling where needed; it must no longer generate, read, or imply done-package content. Public request/input rename to `stageAll` is split across Phase 3A and Phase 3B.
9. Do not claim this phase as independently mergeable target state unless the shared CLI/API/UI/router request contract, user-facing command text, and remote path are aligned in the same integration branch.
10. Preserve existing deterministic git commit reuse, clone retry, and source-branch sync behavior:
   - if the existing baseline finalizes using a valid newly-created or deterministically reused commit SHA, emit `COMMIT_RESULT` for that finalized commit.
   - do not require `COMMIT_RESULT` to be limited to commits created by the current process invocation.
   - do not introduce new automatic recovery for crash-after-git-commit cases.

Exit criteria:

1. Local commit succeeds without `artifacts/done-package.md`.
2. Local commit appends `COMMIT_RESULT`.
3. State still reaches `DONE`.
4. No done-package file is generated.
5. Local result facts use the target technical commit result contract.
6. Local lifecycle metadata no longer exposes done-package path as commit completion metadata.
7. Preserved baseline retry/reuse/source-sync paths finalize with the same `COMMIT_RESULT` contract when they finalize a valid commit SHA.
8. `CommitBubbleResult` and direct CLI/UI-router compile consumers no longer require `donePackagePath`.

## Hard Cutover Rule

The final mergeable implementation must not leave Pairflow in a mixed runtime state where:

1. local commit uses `COMMIT_RESULT` but remote commit still requires `DONE_PACKAGE`,
2. CLI says `--stage-all` but `--auto` still generates done-package,
3. docs describe done-package as active commit behavior,
4. command result still exposes `donePackagePath` as a first-party runtime field,
5. protocol validation accepts `DONE_PACKAGE` as the active commit finalization event.

The work may be implemented in multiple integration slices. Because no active remote bubbles need to be supported during the implementation window, local-first work is allowed on development branches. The final accepted product state is still a hard cutover: main must not be left in a partial target state where local commit has moved to `COMMIT_RESULT` but remote commit, shared result surfaces, CLI/API/UI-router request handling, tests, or live docs still depend on done-package.

## Validation Strategy

1. Protocol validation tests:
   - valid `COMMIT_RESULT`
   - summary rejected
   - missing commit fields rejected
   - unknown metadata rejected
   - done-package fields rejected
2. Local commit tests:
   - succeeds without done-package file
   - does not create done-package file
   - appends `COMMIT_RESULT`
   - transitions to `DONE`
   - result object excludes `donePackagePath`
   - local lifecycle metadata excludes `done_package_path`
   - temporary local stage-all input path stages and commits worktree changes without done-package generation
   - no-staged-files without stage-all remains a clear error
3. CLI tests:
   - help text has no done-package requirement
   - `--stage-all` parses and works
   - `--auto` behavior is removed from target contract
4. API/UI-router tests:
   - request body accepts `stageAll`
   - first-party request body no longer requires `auto`
   - post-cutover `auto` request handling fails clearly rather than invoking old done-package behavior
   - public result projection stays aligned with the Phase 2 no-`donePackagePath` result contract
5. Remote tests:
   - remote commit accepts `COMMIT_RESULT`
   - sync-back excludes done-package content
   - remote SSH output parsing and marker handling do not require done-package content
   - result parity with local commit facts
   - remote commit works in the target state, even though active remote bubbles were not supported during implementation
6. Documentation checks:
   - live docs no longer instruct operators to create or review done-package for commit.

## Risks And Mitigations

1. Risk: hidden first-party consumer still expects `DONE_PACKAGE`.
   Mitigation: search and update all live runtime and docs references before merge.
2. Risk: removal accidentally introduces automatic crash recovery complexity.
   Mitigation: explicitly preserve the current no-new-auto-recovery behavior for local crash-after-git-commit cases.
3. Risk: `--auto` removal surprises operators.
   Mitigation: replace it with explicit `--stage-all` language and tests.
4. Risk: remote commit remains on old continuity behavior.
   Mitigation: local-first implementation is allowed only under the no-active-remote-bubbles implementation-window assumption; remote alignment remains mandatory before the hard cutover is accepted.
5. Risk: `COMMIT_RESULT` becomes a new prose artifact in disguise.
   Mitigation: close the payload fieldset to technical commit facts only.
