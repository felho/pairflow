**Control-Model answers (round-0 skeleton).**

- *Business invariant:* gate-before-commit — a blocking decision
  returns before the commit; version, step, and round are untouched
  (no round burned). Decisions derive from the policy projection
  only.
- *Control model:* the kernel owns the pipeline rung; evaluators are
  read-only, stateless deciders; the process runner owns the spawn
  ("the kernel owns the contract, the runner owns the spawn" — the
  spawn is ch 9's); the registry is static, injected composition.
- *Read-path:* `gate_projection` (derived; exposes no raw
  transcript); retained allow/warn decisions on the committed
  transcript read surface.
- *Forbidden fallback:* an unresolved evaluator never skips
  (`gate_evaluator_unavailable`); a runner failure never allows
  through (runner outcome, block); malformed decision JSON is never a
  business block (runner outcome); nothing on this surface is
  fail-open.
- *Allowed resolution:* config defaults, resolved once at classify
  time — absent `output.mode` ⇒ `exitCode`; absent dispositions ⇒
  `blockTransition`; absent `reason` ⇒ the fixed per-bucket tokens;
  absent `previous_reviewer_verdict` config ⇒ `{required: true}`.
- *Missing-data:* absent `gates` key = ungated step; a config an
  evaluator demands but does not receive is a validate finding; a
  process gate in a workflow with no runtime context is invalid at
  both validation seams.

## Contract rows (every normative statement is a C-row)

| ID | Rule |
|---|---|
| C1 | A step map gains the OPTIONAL `gates` key — the ch8-C7 forward declaration's "first expected" additive growth (ch8-C9's step keyset becomes `role`, `instruction`, `transitions`, + optional `agentConfig`, + optional `gates`). Its value is a map of event-type → gate list. An absent `gates` key means the step has no gated transitions. DECIDED HERE — a recorded divergence from the model's exhibited Config view, which nests gates INSIDE the transition entry (`on_converged: {target, gates}`): ch8-C24's additive-only evolution forbids turning `transitions`' scalar targets into maps, so the binding moves to a parallel step key; the (step, event type) grain is preserved (C2). |
| C2 | The `gates` map is OPEN-KEY (ch8-C13 vocabulary): its keys are event types under ch8-C10's id grammar, and every key MUST be a member of `keys(step.transitions)` — a gate bound to a non-transition event type is a validate finding (dead config, the silent-typo class). The binding grain is (step, event type), realizing the model's `gates_for(step, event_type)`. |
| C3 | Each event-type key's value is a NONEMPTY list of gate maps; authored order IS pipeline order (the runtime's ordered, first-block-wins evaluation consumes it; the format fixes only the order). An empty list is a validate finding — the parser accepts it (probe GP5), so the rule is validator-owned. |
| C4 | A gate map is FIXED-KEYSET: `uses` (required) + `config` (optional map). | C5 | `config` presence is evaluator-specific: REQUIRED for `external.process` (C13) and `declarative.threshold` (C10); OPTIONAL for `pairflow.previous_reviewer_verdict` (C11). A missing `config` where the evaluator requires it is a validate finding. |
| C6 | `uses` grammar: a nonempty string matching `^[a-z][a-z0-9_]*(\.[a-z][a-z0-9_]*)+$` — two or more dot-separated lowercase segments (probe GP3: dotted plain scalars parse as strings). DECIDED HERE — the relation to C10 is stated, not inferred; no C10 row is modified. |
| C7 | The ch8-C21 dotted-path grammar EXTENDS with LIST-INDEX segments for list containers: a gate's error path is `steps.<stepId>.gates.<eventType>[<i>]` (0-based), its fields `steps.<stepId>.gates.<eventType>[<i>].uses` etc. The extension is grammar-additive; existing ch8 paths are unchanged. DECIDED HERE. |
| C8 | The Block A evaluator registry composition is EXACTLY `declarative.threshold`, `pairflow.previous_reviewer_verdict`, `external.process` — STATIC composition (dynamic module loading is a ledger Absent), kernel-side, injected. | C9 | `external.process` is the ONLY registry member with implementation=process; `declarative.threshold` is declarative and `pairflow.previous_reviewer_verdict` is packaged — both in-process inline. | C10 | `declarative.threshold` config keyset: exactly `metric`, `op`, `value` — ALL three required (the model's realized tiny DSL, projected from the golden-trace Config views: `config: {metric: round, op: ">=", value: 2}`; the section's own note: "deliberately tiny: a metric, an op, and a value — not a general expression language" — the `broad-declarative-dsl` ledger Absent is that GENERAL expression language, untouched by this row).
