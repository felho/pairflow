L2 Gate / policy — runtime authorization

A legitimate emit is not yet a permitted one. Before the commit, an ordered pipeline of policy gates decides whether the run's current state allows this action — and a block never burns a round.

By now the kernel has its full L0 foundation and L1 authorization. L1 decided whether an emit is structurally legitimate (role × current_step); L2 adds a runtime decision on top — even a legitimate emit may be blocked by policy given the run's state. This is the operational core of "the workflow is the boss": an early CONVERGED is rejected even though the reviewer judged it ready. The gate is a fourth filter — transition exists (L0b) → role/action authorized (L1) → policy allows now (L2) → commit. Two orthogonal axes organize the space: implementation = declarative | packaged | process and execution = inline | deferred. L2 core realizes only the inline pipeline with declarative DSL primitives and packaged pure pairflow.* policies. Inline external/process gates are L2a; deferred execution is a separate later lifecycle slice (named, not numbered); the route verdict (workflow redirection) is a later routing slice (L3).

Runtime A concrete trace

An early converge blocked without burning the round, then the same emit allowed once the round threshold is met — and the pipeline's second gate runs only after the first allows:

1
codex emits PASS on implement { expected_role: implementer } (version=1, round=1)
authorized ✓ · gates_for(implement, PASS) = ∅ → no gate → commit implement → review; version=2, round=1
2
claude emits CONVERGED on review { expected_role: reviewer } (version=2, round=1)
role ✓ · transition ✓ · capability ✓ → gate pipeline: declarative.threshold (round ≥ 2) → round=1 → block → Rejected(gate_blocked(round_below_min), gate: declarative.threshold); no commit, version stays 2, round not burned, still on review
3
claude emits PASS on review (pass back) { expected_role: reviewer } (version=2)
authorized ✓ · gates_for(review, PASS) = ∅ → commit review → implement; version=3, round advances to 2
4
codex emits PASS on implement (version=3, round=2)
authorized ✓ · no gate → commit implement → review; version=4, round=2
5
claude emits CONVERGED on review { expected_role: reviewer } (version=4, round=2)
gate pipeline: threshold round=2 ≥ 2 allow → next gate pairflow.previous_reviewer_verdict (required) → a prior reviewer verdict exists ✓ allow → commit review → done; terminal — no dispatch
The teeth: on block the kernel returns before the commit, so current_step, version and round are all untouched — an early converge costs nothing and the reviewer can retry later. The pipeline is ordered and first-block-wins; the second gate is reached only because the first returned allow.

Pseudocode The rule behind the trace

One inline gate-pipeline block in HANDLE (after L1 authorization, before the commit), a GateRegistration contract with a definition-ADMISSION seam (admit_definition — the single semantic authority at definition load), a policy-facing gate_projection, and a commit-maintained instance.round:

The pipeline sits between L1's not_authorized and the commit, so a blocked gate never resolves issued_config and never reaches the CAS block — the round is preserved. A process-implementation or deferred evaluator is a valid declaration but returns gate_execution_not_supported here; the inline process contract is realized at L2a, while the deferred runner path (WAITING(gate_pending) + GATE_RESULT) is a separate later lifecycle slice — even an inline process gate is rejected at L2 core, since the contract is unrealized here. Round semantics (L2 owns them, because L2 makes round load-bearing — the declarative.threshold gate reads it). round always starts at 0 (prepared — no work cycle yet); that is a fixed convention, not configurable (like 0-indexing, not a knob). Activation is the first work-cycle arrival and sets round to 1 (the start step being a round-start); each later advancing arrival adds one. advances_round is declared transition semantics in the normalized/pinned template — never inferred from role names, graph shape, target equality, or naming. The authoring form may declare round: { advance_on_arrival_at: [implement] }; the definition loader expands it into explicit per-transition advances_round flags (with per-transition override) for the committed transitions after activation — it does not synthesize a flag for activation (which has no incoming edge). The kernel consumes only the normalized flags — round stays transcript-reconstructable.

The gate is pure: it reads gate_projection and returns a verdict, never mutating the instance or transcript. That keeps "the workflow is the boss" auditable — the decision is a function of declared policy and reconstructable state, not of the actor's goodwill.

Config The template — the converge transition gains a gate pipeline

Only the review step's CONVERGED transition changes: the scalar target becomes a { target, gates } form with an ordered, two-gate pipeline (every other line is unchanged):

The declarative DSL is deliberately tiny: a metric (an allowlisted gate_projection path, here round), an op, and a value — not a general expression language. Richer judgement lives in packaged pairflow.* policies shipped with pairflow; repo-specific custom logic enters later as an external.* process gate (L2a), not as authored code in the template.

  • Scenario coverage: an early CONVERGED is blocked without burning the round; the pipeline runs in order and only converges once the threshold and the previous-verdict gate both allow. Ungated transitions run exactly as at L1.
  • Invariant coverage: gate before commit ✓; round canonical & transcript-reconstructable ✓; gates read-only ✓; all L0a–L1 invariants still hold.
  • Acceptance evidence: success is "the v1 gate families are representable" (table above), not "min_round works" — the mechanism hosts every family, even where the depth lands later.
  • Known gaps (intended): external/process gates (L2a); route/redirection (routing slice/L3); actor-facing communication (L2b); findings vocabulary (later). Each is in Absent.
  • Decision: accepted as the L2 core baseline (light evidence per playbook §2.1).
