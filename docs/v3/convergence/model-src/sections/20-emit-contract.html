EC The emit contract — validated payloads, gate families, pinned idempotency

An actor emit (PASS, CONVERGED, …) stops being just an event name: it is a machine-validated contract. The template declares each op's payload schema against a versioned vocabulary catalog; the kernel validates generically (structure, never meaning — the de-vocabularization rule held); gates split into two semantic families (policy: may you move NOW; verify: is the claim TRUE, by independent evidence, currency-bound); and idempotency pins to the full contract the payload was accepted under. This closes the last v1-parity gap: v1's pass.ts / converged.ts machine-validation and its verify discipline, de-vocabularized. Realizes core-model-todo.md Parts E (except E6) and F, and the A1 digest — the build-order slice the emit-contract memo's paper test measured (11 declarations, zero new machinery).

Three boundaries, drawn once. The summary is a headline: required for humans, never parsed, counted, or used as authority — the structured fields carry the load. Self-report is never evidence: a verify gate reads an independent artifact (exit code, diff, build result), never the actor's claim; "a prior actor verdict exists" is separation, not verification — it stays a policy gate. And no stale-green: verify evidence is trusted only with a currency binding to the state it certifies; a green run on an old commit proves nothing about this one.

3
a buggy client fires one more emit under the now-COMMITTED op_id — with a different payload
the idempotency rung finds the committed entry and compares digests: different ⇒ Rejected(op_id_collision) — key misuse is VISIBLE, never a silent drop of the second payload (an identical replay — same digest — is a plain Duplicate no-op). Before the digest this was a silent Duplicate: the ratified behavior delta

meanwhile on implement.on_pass: the test gate runs (family: verify)
an inline process gate — current BY CONSTRUCTION: it runs now, in this workspace, and its currency_binding records what state the exit code certifies on the GateDecision. A committed-state verify gate would have to record + re-check the same binding — stale-green blocks (a gate_blocked reason, not a new rejection)

Pseudocode The contract machine (diff vs L5)

One lookup (emit_contract_of), one validator (validate_emit_contract — the announced payload rung at its admit-declared call-site home), one offer source (offerable_ops), one digest (payload_digest), the ladder's third re-print (the idempotency rung grows its digest branch), an admission validator, and the gate family rules in admit_definition's EC delta:

The help branch calls the SAME validate_emit_contract — its bespoke required-fields loop is gone, and step.help is simply the HELP_REQUEST op's contract (the per-key payload pattern's third instance, now consumed by the fourth's machine). The digest is computed from the basic-valid payload bytes plus the contract identity — never the schema-normalized value, by NECESSITY: the idempotency rung is the ladder's first, the payload rung runs after selection. A schema-less op still digests (collision detection never depends on a schema existing). The digest rides the actor-emit path only in this slice — the operator/lifecycle paths keep plain Duplicate semantics until their contract identity is designed (a named Absent, so the two-regime state is declared, not silent). Behavior deltas, both ratified: the digest delta (a silent Duplicate over a client bug becomes a visible collision, actor-emit path) and the offer delta (the false offer under an authored capability profile disappears).

Domain What EC adds

The emit contract — a schema, a catalog, a family, a digest
EmitContract (per op, opt-in)
declared on the transition edge (payload:) or the op-family declaration (step.help): required fields + mandatory assertions, typed value domains, versioned-vocabulary subsets, cross-field rules, claim-scoped evidence obligations. Resolved by ONE lookup (emit_contract_of) for the validator, the digest, and the projection
vocabularies (catalog)
versioned, template-referenced (pairflow.findings.v1: severity/timing/layer) — the kernel validates STRUCTURE (enum/subset), packaged modules interpret meaning; a version pins the transcript's meaning forever
gate family (policy | verify)
a semantic dimension on the existing gate declaration, orthogonal to the declarative/packaged/process implementation axis; default policy (zero migration); verify is opt-in and REQUIRES a currency_binding at create (invalid_gate_config otherwise)
payload_digest (identity)
basic-valid payload bytes ⊕ op kind ⊕ schema id ⊕ vocabulary versions — idempotency pinned to the FULL contract the payload was accepted under; the idempotency rung's third re-print compares it: same digest ⇒ Duplicate, different ⇒ op_id_collision
op_contracts (packet)
the E8 projection: per offerable op, the contract requirements the actor must meet — guidance from the same source the kernel enforces, never the source of truth; available_ops ← offerable_ops (the offer calls capability)

Evidence Why we accept EC for now

  • Scenario coverage: a contradictory CONVERGED (P1 finding) is rejected with field-level diagnostics before any state change and without consuming the op_id; the corrected retry reuses that op_id and commits; a later different payload under the now-committed op_id surfaces as a visible collision; the verify test gate certifies THIS workspace state; the packet tells the actor the contract up front.
  • Invariant coverage: offer = gate (by identity) ✓; summary never authority ✓; self-report never evidence ✓; no stale-green ✓; digest pinned to the full contract ✓; catalog versions pin meaning ✓ — and all L0a–L5 + LC1–LC4 invariants still hold.
  • Paper-test reconciliation (emit-contract memo §2): eleven declarations promised, eleven landed — incl. the review round's refinements: the help branch under the generic validator, the same-function offer, the four precisely-scoped rejection names, and the digest's ordering-necessity definition. The two ratified behavior deltas are stated in the pseudocode note.
  • v1 parity: this slice models v1's pass.ts / converged.ts machine-validation (required summary, findings vocabulary + subsets, the no-findings explicit assertion, P0/P1 evidence obligations) and the converged_validation-class verify discipline — the last feature-level gap named by todo Parts E/F.
  • Known gaps (intended): the structured claim model (E6, later), digest on the operator/lifecycle paths (later), emit contracts on operator intents (later), extended authority fields (later), verify governance across runs (L2), deferred verify currency (L9). Each is in Absent.
  • Decision: accepted as the EC baseline (light evidence per playbook §2.1). With this slice, Block A models the full local pairflow-v1 feature set INCLUDING its contract machine.
