LC3b Auto workflow actions — perf-test

LC3a was operator-triggered actions. LC3b adds the trigger: auto mode: an action runs on arrival (no operator), still marker-first — the arrival commit claims WAITING(action_running) + ACTION_RUNNING, then an ActionIntent (produce-not-perform, the DispatchIntent analog) is delivered post-commit, the runner runs, and the result returns as an ACTION_RESULT kernel-event that routes by outcome. Same Workflow Action Contract, new trigger + result-delivery. Diffs against LC3a.

The runner never runs in the arrival commit. “Inline” is only a latency mode of the result event — the sequence is always: ACTION_RUNNING marker committed → ActionIntent delivered → runner runs → ACTION_RESULT event → route. Inline = the event arrives immediately; deferred = later (the async driver / timeout mechanics are thin here, an L9 concern); the contract is identical.

4
(alternate) classify → infra_flake (the perf runner crashed)
the outcome declares a retry policy: attempt_count_in_episode < 3 → RE-CLAIM within the SAME episode_ref (append ACTION_RESULT + a new ACTION_RUNNING, attempt accumulates) → re-issue the ActionIntent. On the 3rd failure → route on_exhausted = human_approval (escalate). The budget is counted from the transcript, not a hidden field
Bounded retry is not a general rule for negative outcomes — it fires only for an outcome that declares retry. regression (a business result) routes to implement; infra_flake (execution uncertainty) retries then escalates. The attempt count is anchored to the episode_ref opened at the fresh arrival, so a later round's re-entry starts clean.
